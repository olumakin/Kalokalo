## Findings, highest priority first

### A01 — P0 — Dixon–Coles low-score factors are reversed

**Evidence:** `src/models/dixon_coles.py:59–70`, `src/models/simulator.py:14–40`; `tests/test_dixon_coles.py:61–67` omits the asymmetric cells.

With home goals `x ~ Pois(lambda)` and away goals `y ~ Pois(mu)`, the correction must use `1 + lambda*rho` for `(0,1)` and `1 + mu*rho` for `(1,0)`. Code uses the opposite rates. The [goalmodel maintainer's implementation](https://github.com/opisthokonta/goalmodel/blob/master/R/dixoncoles.R) independently implements these factors. The model's original research reference is [Dixon and Coles (1997)](https://academic.oup.com/jrsssc/article-abstract/46/2/265/6990546).

**Verification:** Executed the actual extracted `tau` function with scalar substitutes for NumPy's `ones_like`/`where`: at lambda=1.4, mu=1.1, rho=0.1, code gives `tau(0,1)=1.11` instead of 1.14, and `tau(1,0)=1.14` instead of 1.11. Algebraically the full-support joint mass becomes `1 + exp(-lambda-mu)*rho*(lambda-mu)^2`, rather than 1. For this example it is 1.0007387649876152. These are deterministic checks, not a fitted-model benchmark.

**Impact:** Training optimizes a misnormalized likelihood; inference renormalizes a different distribution. Home/away and draw probabilities, fitted parameters, EV, and historical conclusions can all change.

**Remediation/closure:** Correct the factors; test both asymmetric cells with unequal goal rates, untruncated mass cancellation, marginal preservation, and training/inference agreement. Invalidate model caches and rerun historical evidence after correction.

### A02 — P0 — Synthetic and static observations can produce ordinary recommendations

**Evidence:** `app.py:207–228,301–302,354–384`; `src/ingestion/demo_data.py:62–106`; `src/ingestion/odds_feed.py:223–269`; `src/pipeline.py:175`; `data/fixtures/upcoming.csv:1–4`.

The default history is simulated. The final automatic fixture fallback is three fixed matches dated 2026-09-20/21 with fixed decimal odds. CLI defaults to that file. Generated history can be combined with live odds, not just demo fixtures. The same prediction/qualification and ledger code serves all these paths; no production eligibility check rejects synthetic training, sample fixtures, or absent provenance. The UI does identify the sample feed, but a label does not prevent staking output or ledger contamination.

**Remediation/closure:** Remove synthetic/sample providers from the production dependency path. If retained for tests, package them separately and prohibit production imports. Unavailable selected sources must yield an explicit unavailable result and no recommendation. Every published prediction must reference verified historical and market snapshots. Failure-injection tests must produce zero replacement fixtures and zero production predictions.

### A03 — P0 — Cross-league team codes merge distinct clubs

**Evidence:** `src/ingestion/normalizer.py:36–57`; `config/team_mappings.json`; `src/pipeline.py:110–125`; `src/models/dixon_coles.py:212–228,347–350`; `src/validation/backtest.py:49–75`.

Actual mapping inspection found `MON` assigned to Monza in I1 and Monaco in F1. Main pipeline and simple backtest pool leagues into one model indexed only by team code. This combines their ratings and also shares scoring baseline/home advantage between selected leagues. The gate harness instead fits per league, so its evaluation does not validate the same production behavior.

**Remediation/closure:** Use stable team IDs scoped by competition (provider IDs mapped to internal IDs) and fit one model per league. Route fixtures to their league's model. Verify that adding F1 history cannot change an I1 model or fixture prediction, and that both MON clubs remain distinct.

### A04 — P0 — Failed, substituted, or unknown-team models remain eligible

**Evidence:** `src/models/dixon_coles.py:273–331,335–358`; `src/pipeline.py:34–50`; `src/validation/gate_harness.py:253–294`; `app.py:426`.

Failed optimization switches rho to zero and refits. If that fit also fails, parameters are still published. Outer profile-search success is not checked. Unknown teams get zero attack/defence ratings. Main qualification only checks probability and EV, so none of these states stops a recommendation. The gate harness excludes unseen teams but still scores and qualifies nonconverged/fallback fits. The UI warning is informational.

**Remediation/closure:** Return a typed failed-fit/unknown-team result; do not substitute independent Poisson or neutral ratings in production. Require successful inner and outer optimization, finite parameters, approved model version, and supported identities before inference or qualification. Test each failure state through both API and evaluation paths.

### A05 — P0 — Invalid probability models are repaired by clipping

**Evidence:** `src/models/dixon_coles.py:99,148–149,257–279`; `src/models/simulator.py:29–40`.

The fixed rho interval [-0.3,0.3] does not guarantee positive low-score factors for all goal rates. For lambda=mu=4 and rho=0.1, `tau(0,0)=-0.6`. Training clips tau to `1e-10`; prediction clips negative cells to zero then normalizes. This masks invalid parameters and creates different training and inference semantics. All candidate factors, not only observed cells, must be admissible.

The 10×10 grid also discards a variable tail with no retained-mass check. As a stress example, independent Poisson rates of 8 retain only 0.51355 of total mass on that grid before normalization. This is not evidence that a typical fitted match reaches 8; it disproves the documented unconditional small-tail guarantee.

**Remediation/closure:** Constrain admissible rho jointly with rates, reject nonfinite/negative probability states, and monitor retained mass before normalization. Use an adaptive grid with a declared tail tolerance and hard resource limit; reject unsupported cases at that limit. Test extreme rates, boundary rho, and all four corrected tau cells.

### A06 — P1 — Gate can approve a selection worse than baseline

**Evidence:** `src/validation/clv.py:68–99`; `src/validation/gate_report.py:19–65`; `docs/gate-evaluation.md`.

Baseline and flagged CLV are calculated, but the decision reads only flagged bounds against zero. An actual extracted-function probe with baseline CLV 10% (CI 8–12%) and flagged CLV 2% (CI 1–3%) returns `proceed_with_leagues`. This contradicts the documented above-baseline selection test. Production qualification does not consult a gate report at all.

**Remediation/closure:** Estimate a joint matchweek-block bootstrap confidence interval for flagged-minus-baseline CLV on the same resampled weeks, preserving their overlap. Require both positive absolute flagged CLV and positive incremental CLV, sufficient independent weeks, and finite diagnostics. An approved report must be tied to an exact model/data/config version and enforced by the recommendation service. Add the counterexample as a regression case; failed/inconclusive evidence must never authorize recommendations.

### A07 — P1 — Audit records are forgeable under the shipped anonymous policies

**Evidence:** `supabase/schema.sql:45–52`; `src/tracking/supabase_ledger.py:53–69,101–141`.

Policies permit unrestricted INSERT and SELECT for `anon`. With the required table grants, any caller holding the publishable key can read rows and insert fabricated predictions or settlements. Denying UPDATE/DELETE prevents one class of mutation, not forged new evidence. The schema has no owner identity, settlement foreign key, or probability/odds constraints. Actual deployment grants were not inspected; the policies alone do not prove either successful access or a live breach. [Supabase documents the distinction between grants and row policies](https://supabase.com/docs/guides/database/postgres/row-level-security).

**Remediation/closure:** Deny anonymous writes, authenticate users, and authorize compute/settlement operations server-side. Use least-privilege database roles and constraints. Test anonymous access, cross-user access, forged predictions, duplicate settlements, and invalid probabilities against an isolated database.

### A08 — P1 — History can stay stale indefinitely; upcoming status is not enforced

**Evidence:** `src/ingestion/historical.py:48–75,79–104`; `app.py:140–153`; `src/ingestion/odds_feed.py:29–48,155–269`; `src/pipeline.py:110–125`.

An existing season CSV is returned forever unless `force=True`; normal callers do not request it. Streamlit's six-hour cache expiry does not refresh this disk cache. Fixture normalization does not reject past kickoffs, invalid dates, duplicates, nonfinite prices, or invalid decimal odds. The static card naturally expires. Main fitting uses all supplied history rather than an explicit fixture cutoff and configured rolling window, so scoring an old fixture can include later results.

**Remediation/closure:** Version and timestamp source snapshots, refresh active seasons, validate completeness, and block stale or already-started fixtures. Require explicit UTC forecast time and training cutoff, history strictly before cutoff, and the configured rolling window. Test active-season updates, stale snapshots, malformed fixtures, and historical replay without lookahead.

### A09 — P1 — Consensus odds are treated as an executable price

**Evidence:** `src/ingestion/odds_feed.py:120–151`; `src/pipeline.py:43–50`; `src/ingestion/data_loader.py:60–100`.

Each outcome is averaged independently across available bookmaker prices; the three legs can come from different bookmaker subsets. Bookmaker IDs, update timestamps, event IDs, and quote availability are discarded on normalization. EV and Kelly then use that average draw price, which may be unavailable at any individual bookmaker. Historical closing selection may silently substitute market averages for Pinnacle closing. Without source-time identity, these comparisons do not establish executable returns or a consistent same-book CLV series.

**Remediation/closure:** Keep complete timestamped bookmaker quotes. Separate a declared consensus estimator from the specific executable quote used for EV. Choose and record one explicit evaluation price policy; missing required legs exclude the observation with a reason instead of choosing a different tier. Evaluate fees and availability only where supported by real execution data.

### A10 — P1 — Historical ingestion does not assemble the gate's required data

**Evidence:** `src/ingestion/normalizer.py:24–28,112–117`; `src/ingestion/data_loader.py:60`; `src/validation/gate_harness.py:158–171,261–294`; `tests/test_gate_pipeline_integration.py:19–47`.

Normalization retains one odds triple and drops opening/closing raw columns. `select_entry_close_odds` has no production call site. The harness expects already-enriched `entry_*` and `close_*` columns; missing prices become NaN and unqualified rows. The integration test constructs synthetic priced data directly, so it bypasses this missing real-data assembly step. No full-corpus evidence artifact was found in the inspected project.

**Remediation/closure:** Build an explicit historical snapshot-to-evaluation dataset service that preserves both price legs and provenance. Test with representative archival CSV schemas, including absent required columns. Run out-of-sample evaluation only after A01–A09, and distinguish software smoke tests from empirical model evidence.

### A11 — P1 — Settlement accounting conflates predictions with positions

**Evidence:** `pages/3_Ledger.py:64–104`; `src/tracking/ledger.py:67–92`; `src/pipeline.py:133–149`.

Repeated runs append duplicate fixture predictions. Reconciliation combines the first odds with the maximum stake, computes one PnL/CLV, then assigns it to every prediction with that match ID. Example: winning draw records at (stake=.01, odds=3) and (.02,4) should contribute .02 and .06 if both were real positions. Current aggregation produces .04 for each record. A non-staked record may also receive PnL. Predictions are not evidence that a bet was placed.

**Remediation/closure:** Separate immutable prediction snapshots, explicit position/execution records, and result events. Calculate return for each actual position using its own quote and stake. Forecast-only records must have no realized trading PnL. Add repeated-run, differing-odds, zero-stake, partial-settlement, and idempotency checks.

### A12 — P1 — Local/remote ledgers diverge and cannot ensure durable publication

**Evidence:** `src/tracking/ledger.py:26–65`; `src/tracking/supabase_ledger.py:72–141`; `app.py:361–384`; `pages/3_Ledger.py:14–16,99`; `src/pipeline.py:152–170`.

Local recording reads and rewrites the entire file per row without a transaction or concurrency lock. Concurrent sessions can lose updates. Local outcomes mutate original records. UI reads and settles only local data; remote settlement helper is unused. CLI writes only locally. Remote prediction rows omit qualification, stake, training source, dataset/config hashes, and season; model version is a fixed string. A fresh run UUID means repeated user runs are not deduplicated. Write failures are counted but predictions remain usable.

**Remediation/closure:** Use one transactional Postgres source of truth, immutable run/prediction metadata and settlement events, and request idempotency. Expose results only after the authoritative transaction succeeds. Local CSV/Parquet becomes an explicit export. Preserve legacy imports with `provenance_unknown`; do not fabricate missing metadata.

### A13 — P1 — Input and date validation is weaker than documentation claims

**Evidence:** `src/ingestion/data_loader.py:103–154`; `src/ingestion/normalizer.py:93–106`; `src/ingestion/odds_feed.py:29–48`; `src/validation/gate_harness.py:79–91`; `app.py:307–309`.

Historical validation checks null and negative goals, not finite integer goals, blank team strings, supported competitions, actual datetime dtype, or positive finite odds on every supplied leg. Raw goals are cast to integers before validation, potentially truncating fractional values or raising on text. Uploaded canonical dates use a parser that may raise before the validation report. `assert_datetime_utc` accepts naive datetimes; it does not enforce UTC. Unknown team names are shortened to three characters, introducing additional collisions.

**Remediation/closure:** Introduce strict boundary schemas with finite numeric constraints, explicit source date semantics, UTC event times, separately represented date-only historical records, stable identity resolution, and reasoned exclusions. Do not invent kickoff times from date-only data. Unknown identities must stop that fixture, not create a guessed club code. Validate raw data before coercion.

### A14 — P1 — Reproducibility and training semantics drift between paths

**Evidence:** `src/validation/gate_harness.py:94–105,215–228`; `src/models/dixon_coles.py:205–208,250–255`; `src/pipeline.py:110–125`; `config/settings.yaml:17–25`.

Fit-cache keys omit data content, rolling window, optimizer settings, and minimum match count. Reusing a date/league/xi/commit key after changing those inputs can load the wrong model. Unknown code versions and dirty working trees are also indistinguishable. Gate fitting uses last observed match + one day as decay origin; simple backtest passes actual prediction time. Because ridge penalty is unscaled, this difference can change the optimum, particularly across long gaps. Published centered warm-start ratings are copied directly into a reference-pinned basis without the matching basis/intercept conversion. `goal_grid_size` and `rho_init` do not control the main computations as their settings suggest; `xi_grid` is not swept.

**Remediation/closure:** One training specification and artifact hash must include data snapshot, cutoff, league, feature target, all configuration, code/build version, and dependency version. Use the same fit/inference services in live and evaluation paths. Convert warm starts into the optimizer basis or use a consistent centered parameterization. Verify cache invalidation and live/replay parity.

### A15 — P1 — Exposure limits apply only inside one run

**Evidence:** `src/pipeline.py:79–89`; `src/analytics/edge.py:33–48`; `src/tracking/ledger.py:41–65`.

Caps consider only the provided prediction batch, not existing positions or prior runs. Re-running a slate can recommend further exposure without reservation/deduplication. Duplicate fixture rows collapse to one dictionary entry during capping, then the capped stake is assigned to every duplicate row; their total can exceed the intended batch limit. No actual bankroll or position state is maintained.

**Remediation/closure:** Deduplicate fixture identities before qualification. Treat current percentages as hypothetical sizing until an authenticated portfolio and transactional exposure reservation exists. If position features remain in scope, enforce limits against open positions and the declared portfolio calendar in a database transaction.

### A16 — P2 — Drawdown and evidence sufficiency can mislead

**Evidence:** `src/validation/metrics.py:60–64`; `pages/2_Backtest.py:93–102`; `src/validation/clv.py:24–65`; `src/validation/bootstrap.py:52–85`; `src/validation/calibration.py:19–48`.

Drawdown starts its peak at the first cumulative result rather than initial zero equity: one losing unit yields reported drawdown 0 instead of -1. Same-day bet ordering also affects the chart. CLV sufficiency counts rows, not independent blocks; more than ten rows in one week yields undefined block intervals while `insufficient_sample=False`. Calibration returns optimizer parameters without checking convergence. Standalone paired bootstrap resamples rows, so it is not by itself a dependence-aware time-series significance test.

**Remediation/closure:** Include initial equity, declare settlement ordering or aggregate daily returns, check finite valid prices and intervals, require independent-block sufficiency, and expose failed calibration as unavailable. Test the one-loss case, one-block case, NaN inputs, and optimizer failure. Use joint blocks for temporal comparative statistics.

### A17 — P2 — UI confidence labels and displayed evidence overstate readiness

**Evidence:** `app.py:48,530–582`; `pages/2_Backtest.py:78–120`; `pages/1_Model_Diagnostics.py`; `pages/3_Ledger.py`.

Every draw probability below 27.5% is labelled MODERATE; even a very small value gets that wording. The fixed threshold has no linked calibration evidence. Primary exact-score probability is computed but omitted while the alternative score's probability is shown. Forecast-only cards still offer an expandable bankroll recommendation. Synthetic training provenance is not a per-prediction field. Backtest results persist in session state when inputs change. Documentation says notices appear on every page; source search finds the notice only on Matchday.

**Remediation/closure:** Show numeric probabilities with source/run/fit status and the probability of the most-likely score. Remove unsupported qualitative ratings or validate their thresholds on held-out data. Bind results to immutable input/run IDs. Distinguish forecasts, model-estimated price comparisons, and separately approved recommendations in API and UI. This is a product-consistency finding, not a legal compliance assessment.

### A18 — P2 — Shrinkage and optional xG fitting need separate validation

**Evidence:** `src/models/dixon_coles.py:155–162,175–183,218–226,309–325`; `src/ingestion/sources.py:127–144`.

Penalty is applied to free ratings relative to the pinned reference, not to all teams' centered ratings; subsequent recentering does not make the penalized objective reference-invariant. Raw match counts, not time-weighted information, determine penalty strength. In xG mode the likelihood uses fractional targets, while tau activates only on exact integer low-score cells; many xG rows therefore provide no ordinary low-score information for rho. This experimental method is documented as approximate, but has no separate release gate.

**Remediation/closure:** Test reference-choice sensitivity and choose a mathematically consistent centered penalty. Treat xG as a separate model specification with its own likelihood, version, and held-out evidence; do not substitute it into the goal-count model under the same approval. These are modeling-design risks, not measured accuracy claims from this audit.

### A19 — P2 — Documentation and verification labels contradict the implementation

**Evidence:** `README.md`, `docs/architecture.md`, `docs/invariants.md`, `docs/gate-evaluation.md`, `lessons.md`, `tasks/lessons.md`, `roadmap.md`.

Examples: defence is added in code (defensive weakness), while existing equations subtract it; code recenters mu0 by adding both rating means; rho bounds are [-0.3,0.3], not [-0.15,0.10]; 0.15 is 15%-Kelly, not quarter-Kelly; the local ledger is mutable; remote outage behavior is fail-open; fixture TTL is 15 minutes, not the claimed verified 3600 seconds; a bounded search budget does not guarantee convergence. No constant rho interval ensures positivity for arbitrarily large rates. Claims of baseline gate enforcement, UTC enforcement, complete remote settlement, and universal notices are also unsupported.

**Remediation/closure:** Treat these earlier descriptions as historical intent. This dated audit and the proposed migration document supersede conflicting readiness claims. Replace VERIFIED labels with reproducible evidence references when implementation checks exist. Do not mark this audit's findings fixed merely because documentation has been added.

### A20 — P2 — Runtime assurance and service boundaries are missing

**Evidence:** `requirements.txt`, `Dockerfile`, `Procfile`, `app.py:298–390`, `pages/2_Backtest.py:51–65`, test inventory.

UI requests synchronously download, fit, score, and write records. There is no dedicated API boundary, durable compute queue, application-level authorization, model registry, or unified publication transaction. Most dependency ranges are open-ended and no CI workflow is present in the inspected checkout. The available Python lacks NumPy, SciPy, pandas, PyYAML, and pytest. Existing tests include synthetic/mocked integrations and intentionally assert several fallback behaviors; passing them would not establish this user's stricter requirement.

**Remediation/closure:** Follow the [frontend/backend migration proposal](frontend-backend-migration.md). Pin a reproducible environment in implementation work, add invariant and contract checks, and run integration tests against isolated services before rollout. No dependencies were installed during this read-only code audit.

No randomly generated score is directly used by `top_scorelines`: it extracts the fitted matrix's largest cells. This does **not** make the forecast trustworthy when its training observations are synthetic or its model is invalid. Historical datasets and immutable model artifacts are necessarily stored snapshots; they are permitted as traceable real evidence, not as silent replacements for missing current inputs. Under the strict target, no automatic provider/model/price substitution is permitted. Retries of the same operation are not substitutions.

## Architecture conclusion

Keep the Python numerical work, after correcting it. Move orchestration and persistence behind one authenticated Python API, run fitting/evaluation in workers, and use a separately deployed web frontend. Start with a modular backend rather than many microservices. See [the migration proposal](frontend-backend-migration.md) for boundaries, API contracts, failure behavior, data migration, acceptance gates, and rollout order. No production release or migration has been performed.
